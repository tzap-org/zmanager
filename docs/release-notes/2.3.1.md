# ZManager CLI 2.3.1 Release Notes

**Status: draft for 2.3.1.** Review API compatibility before publishing; adjust the release target if these public changes require a different semver level.

## Breaking Rust API changes

- `TzapLocalIdentityInventory` adds `storage_revision` to reject stale concurrent writes. Callers using struct literals should set it to `None` for a new inventory, or use `..TzapLocalIdentityInventory::empty()` where appropriate. Inventories loaded from a store carry the revision needed for their next save.

## Correctness and safety

- Forced archive publication preserves the previous file if publishing its replacement fails. TZAP archive and sidecar updates are rolled back together, and stale sidecars are removed when a forced replacement no longer emits one.
- Extraction rejects replacing a destination directory with an archive file. Batch extraction applies byte and entry limits cumulatively.
- Archive tests fail when integrity testing is unsupported. CLI test filters that match no entries report an error instead of testing the whole archive.
- `--test-after` carries credentials forward and preserves incomplete-creation failures.
- Browser extraction reports the materialized destination path and bytes written, including duplicate paths.
- Identity stores detect stale inventory revisions instead of overwriting concurrent updates.
- LocalSend receiver startup and send IDs are reserved safely; expired transfer responses are reported instead of appearing successful.
- Apple Archive creation and reading honor passwords; unsupported volume-size requests are rejected.

## Build and release changes

- The declared Rust minimum is 1.95, matching the locked dependency graph.
- The installer prepares pinned sibling dependencies for source builds, and notarization polling continues after an individual draft fails.
- Crates.io publication includes the workspace dependency crates.
