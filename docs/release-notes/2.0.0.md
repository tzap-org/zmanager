# ZManager CLI 2.0.0 Release Notes

ZManager CLI 2.0.0 completes the TZAP identity workflow with certificate revocation, hosted enrollment and renewal across local/dev/staging/prod environments, and recipient key generation. It also delivers a significantly faster `.tzap` listing path, a build revision embedded in `zm --version`, and a breaking tightening of signed sharing.

## Breaking Changes

- **Signed sharing requires explicit certificate selection**: `zm share` now requires `--certificate-id` so the certificate used for RootAuth signing is always explicit. Invocations without it fail with a usage error.
- **Version string includes build revision**: `zm --version` now prints `zm 2.0.0 (<short-git-sha>)` (with a `-dirty` suffix for uncommitted builds). Set `ZMANAGER_BUILD_REV` at build time to override the revision.

## Highlights

- **Device revocation**: New `zm device revoke` command revokes a personal device through the TZAP sign API.
- **Hosted enrollment and renewal**: `zm cert enroll` and `zm cert renew` now support hosted TZAP sign APIs via `--service-base-url`, with `--trusted-root-cert` for staging roots, `--org-id`, and a configurable requested certificate lifetime (`--requested-validity-seconds`, default 90 days).
- **Auth environment selection**: `zm auth login`, `zm auth status`, and `zm auth account` accept `--environment <local|dev|staging|prod>`; a new `staging` environment points at `https://staging.tzap.org`.
- **Recipient key generation**: New `zm contact keygen [--label <name>]` generates a labeled local recipient key for sharing.
- **Fast TZAP listing**: `.tzap` listing now reads authenticated index metadata directly instead of decoding every tar payload member, making `zm list` on large archives substantially faster. Entries expose `created`, `uid`, `gid`, `mode`, `size`, and `compressed_size`, with compressed/uncompressed totals and a compression ratio summary; PAX column and metadata-gap fixes for Apple Archive entries.
- **Public identity catalog**: New `.identity-catalog.json` support with purpose-scoped secret references (`signing_key`, `recipient_key`, `session`) lets readers access public TZAP identity metadata without ever hydrating private key bytes.
- **End-to-end integration testing**: Added E2E coverage against a staging certificate with `scripts/staging-integration.sh`.
- **Repository cleanup**: Removed the vendored `vendor/unrar` source tree; RAR support now depends on the published crate.
- **Quality**: Added unit and integration tests and fixed miscellaneous bugs across the CLI and core.

## Known Backend Limits

- Creation is intentionally limited to ZIP, TAR.ZST, TZAP, 7z, and TGZ.
- Apple Archive support (reading/writing `.aar` and `.aea`) is available exclusively on macOS and iOS targets.
- Editing an existing archive in place is not supported. Extract, modify, and create a new archive instead.
- RAR creation is not supported.
- Raw single-file streams extract to one output file; they are not archive containers.
- `--to-stdout` is for selected regular file data, not directories, links, or special entries.
